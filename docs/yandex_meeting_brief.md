## 1. Проект / Project

**Kuzet AI** — система компьютерного зрения для безопасности школ.
Работает в реальном времени: обнаружение насилия / буллинга, оружия (нож / пистолет), огня и
дыма — по видеопотокам с IP-камер в коридорах и помещениях школ. Алерты отправляются
сотрудникам безопасности в течение нескольких секунд. Всё локализовано на русском языке.

**Kuzet AI** is a real-time computer-vision school-safety platform. It detects violence/bullying,
weapons (knife/pistol), fire, and smoke from IP camera streams in school corridors and rooms.
Alerts reach security staff within seconds. All UI is in Russian.

## 3. Архитектура системы / Pipeline

Пайплайн от входного кадра до алерта (схема прилагается):

```
IP-камеры (RTSP)
   ↓
Motion Gate          — отбрасывает статичные кадры (CPU, без модели)
   ↓
Pose + Track Spine   — позы людей + трекинг (RTMO / YOLOv8-pose + ByteTrack)
   ↓  ↓  ↓
Skeleton Action    Object Detector    Zone/PPE
(насилие/буллинг)  (оружие, огонь)   (геометрия)
   ↓
Confidence Gate      — если неуверен → тяжёлая RGB-модель (VideoMAE/X3D)
   ↓
Event Service        — дебаунс, порог на камеру, подавление ложных срабатываний
   ↓
Clip Store / Alerting / Dashboard
   ↓
Offline Loop (облако) — просмотренные алерты → переобучение → обновление весов OTA
```

### Текущее состояние репозитория (сегодня)

| Модуль | Модель | Статус |
|---|---|---|
| Поза + трекинг | **YOLOv8n-pose + ByteTrack** (17 ключевых точек) | ✅ в коде |
| Насилие / буллинг | **X-CLIP base-patch32** (8 кадров, 224²) + **ViT-base** per-frame | ✅ в коде |
| Оружие | **3× YOLOv8** (имг. 1280/960/640) + **OWLv2-base** верификатор | ✅ в коде |
| Огонь / дым | **YOLOv8n-fire** (keremberke / local) | ✅ в коде |
| Motion gate | — | ⬜ не построен |
| INT8 / TensorRT | — | ⬜ не построен |
| ST-GCN (скелетная модель) | — | ⬜ целевая архитектура |

**Стек:** Python 3.12, PyTorch, Ultralytics YOLOv8, HuggingFace Transformers.
**Нет TensorRT / INT8 сегодня** — это целевое состояние после оптимизации.

### Самые тяжёлые компоненты (сейчас)

| Компонент | Тип | Нагрузка |
|---|---|---|
| X-CLIP base-patch32 | Видео-трансформер (8 кадров) | **Тяжёлый** (~200–400 мс/окно) |
| OWLv2-base (верификатор оружия) | Open-vocab vision transformer | **Тяжёлый** (раз в 15 кадров) |
| YOLOv8n-pose | YOLO nano | Лёгкий (~10–15 мс/кадр на GPU) |
| YOLOv8 (оружие, огонь) | YOLO small–medium | Средний |

**VRAM при загрузке всех моделей:** ~3–4 ГБ → помещается на T4i (24 ГБ), можно шарить между
потоками.

**Throughput сегодня:** ~**1–5 потоков/GPU** (Python/PyTorch без оптимизации).  
**Цель после TensorRT + ST-GCN + motion gate:** ~**40–200 потоков/GPU** (по данным NVIDIA
DeepStream бенчмарков для аналогичных пайплайнов).

## 4. Финансовая модель — что нам нужно от Яндекс Облака

> Это главная цель встречи. Ниже — конкретные вопросы с пояснением, почему каждый важен.

### A. Доступность GPU в регионе Казахстан

- По документации `yandex.cloud/ru-kz/docs/compute/concepts/gpus`, в регионе Казахстан сейчас
  доступны **только `standard-v3-t4i` (Intel Ice Lake + T4i, 24 ГБ)**. Это верно?
- **Roadmap:** когда в KZ появятся A100, L4, L40S или аналог?
- Если нужен A100/H100 — можно ли обрабатывать **видео из школ (данные несовершеннолетних)**
  в регионе `ru-central1`? Какие требования к резидентности данных?
- Поддерживается ли **MIG** (Multi-Instance GPU) на T4i в KZ? Это позволит нарезать один GPU
  на несколько малонагруженных потоков.

### B. Цены и скидки (ключевые входные данные для модели)

- Подтвердите актуальные тарифы T4i в KZT (GPU·ч, vCPU·ч, ГБ RAM·ч).
- **CVoS** (committed volume of services): какой % скидки при объёме на **1 год** и **3 года**
  для нашего масштаба (1 170 школ)?
- Есть ли **enterprise / государственные тарифы** для образования?
- **Стартовые гранты или кредиты** для пилота?
- Подтвердите: при **остановке GPU-VM** вне школьных часов — плата за GPU **не начисляется**
  (только диск + статический IP)? (Биллинг per-second?)

### C. Throughput и serving-стек (самый важный вопрос)

- Какой **reference S** (потоков/GPU) вы видели для видеоаналитики (pose + action + детектор)
  на T4i? Есть ли бенчмарки DeepStream / Triton для аналогичных задач?
- Что рекомендуете для serving: **Triton Inference Server**, **NVIDIA DeepStream**,
  **Managed Kubernetes + GPU autoscaling**?
- Как лучше организовать **autoscaling под school-hours профиль** (старт утром, стоп вечером +
  пиковые нагрузки на переменах)?

### D. Сеть, хранилище, compliance

- Стоимость **ingress** (RTSP-потоки в облако) — бесплатно?
- **Egress** (алерты, дашборд наружу) — тариф ₸/ГБ?
- **Object Storage** для кольцевого буфера клипов (последние 72 ч событий) — ₸/ГБ·мес?
- **Приватное подключение** школ (Cloud Interconnect / VPN) — тарифы?
- **SLA / uptime** гарантия? Что происходит при сбое: школа «слепнет»?
- **Гарантии резидентности данных** для видео несовершеннолетних в KZ-регионе?

### E. Архитектура

- Рекомендуете ли вы **pure cloud** или поддерживаете **edge/hybrid** (вычисления на
  оборудовании в школе, только события в облако)?
- Какие managed-сервисы подходят: Managed K8s, Cloud Functions, IoT Core?

## 5. Два ответа, которые важнее всего

1. **S — потоков на GPU** для нашего пайплайна (определяет количество GPU → главный множитель).
2. **% скидки CVoS** при нашем объёме (определяет итоговую ставку).
